# IBM Anti-Money Laundering Graph Project

An end-to-end machine-learning project for ranking potentially suspicious transactions using the IBM synthetic anti-money-laundering dataset. The project cleans transaction data, joins account metadata, engineers behavior and network features, trains baseline and XGBoost models, and exports ranked alerts.

> This project is for research and education. A laundering probability is a risk score for investigation, not proof of wrongdoing.

## What the project does

1. Cleans the IBM transaction CSV.
2. Joins sender and receiver account metadata.
3. Builds rolling behavior features from past transactions.
4. Builds graph-style fan-in, fan-out, and rapid-forwarding features.
5. Trains LightGBM and XGBoost models.
6. Evaluates models by precision, recall, PR-AUC, and fixed alert budgets.
7. Scores a prepared batch and ranks the highest-risk transactions.

The main pipeline is chronological to reduce accidental use of future data:

```text
HI-Small_Trans.csv
  -> transactions_clean.parquet
  -> transactions_with_accounts.parquet
  -> transactions_with_behavior.parquet
  -> transactions_with_graph_features.parquet
  -> ranked predictions
```

## Dataset

This repository does not include the large IBM CSV files. Download or provide a dataset yourself and place the required files in the project root.

| File | Purpose |
|---|---|
| `HI-Small_Trans.csv` | Main training and test transaction data |
| `HI-Small_accounts.csv` | Account metadata for HI-Small |
| `HI-Medium_Trans.csv` | Optional unseen-data validation |
| `HI-Medium_accounts.csv` | Account metadata for HI-Medium |

The source files are ignored by Git because they are large. The HI-Small data has approximately 5.08 million transactions and is highly imbalanced: only about 0.102% are labeled as laundering.

## Installation

Open PowerShell in the project directory:

```powershell
cd "D:\Sem 5\machine learning\lab\ibm aml project"
```

Create and activate a virtual environment:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, enable scripts for your user account:

```powershell

.\.venv\Scripts\Activate.ps1
```

Install dependencies:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Place `HI-Small_Trans.csv` and `HI-Small_accounts.csv` in the project root.

## Run the complete training pipeline

Run every command from the project root.

### 1. Clean and prepare transactions

```powershell
python preprocess_data.py
```

Output:

```text
processed/transactions_clean.parquet
processed/audit_report.txt
processed/class_counts.csv
```

### 2. Join account metadata

```powershell
python join_account_metadata.py
```

Output:

```text
processed/transactions_with_accounts.parquet
```

### 3. Add rolling behavior features

```powershell
python add_behavior_features.py
```

Output:

```text

```

### 4. Add graph and forwarding features

```powershell
python add_graph_features.py
```

Output:

```text

```

### 5. Train models

LightGBM baseline:

```powershell
python train_baseline.py
```

```powershell
python train_xgboost.py
```

The final model and policy are saved under `processed/`:

- `xgboost_graph_model.json`
- `final_xgboost_config.json`
- `final_xgboost_metrics.txt`
- `xgboost_graph_feature_importance.csv`

## Score transactions

The model requires the 37 engineered columns. Raw transaction rows cannot be scored directly unless they have passed through the full feature pipeline.

Ready-made model-ready samples are generated by the project:

```powershell
python export_test_samples.py
```

Score a batch:

```powershell
python predict_batch.py `
  --input "processed\sample_laundering.csv" `
  --output "processed\my_predictions.csv" `
  --alerts 25
```

The output contains:

- `laundering_probability`: model risk score
- `alert_rank`: rank for a selected alert
- `is_alert`: whether the row is inside the requested alert budget

By default, `predict_xgboost.py` scores rows in or after the held-out validation period:

```powershell
python predict_xgboost.py
python predict_xgboost.py --all-rows
```

To score a custom batch, provide a CSV or Parquet file that contains every model feature:

```powershell
python predict_batch.py --input "path\to\model_ready.parquet" --output "output\predictions.csv" --alerts 1000
```

## Project structure

```text
.
|-- preprocess_data.py              Clean the raw transaction CSV
|-- join_account_metadata.py        Join sender and receiver accounts
|-- add_behavior_features.py        Add rolling account behavior features
|-- add_graph_features.py           Add network and forwarding features
|-- train_baseline.py               Train LightGBM baselines
|-- train_xgboost.py                Train the XGBoost model
|-- threshold_analysis.py           Compare probability thresholds
|-- alert_budget_analysis.py        Compare fixed alert budgets
|-- finalize_xgboost.py             Save the final model policy
|-- predict_batch.py                Score a prepared CSV or Parquet batch
|-- predict_xgboost.py              Score the held-out graph feature table
|-- export_test_samples.py          Export positive and negative samples
|-- view_parquet.py                 Export a small Parquet preview
|-- PROJECT_SUMMARY.md              Detailed technical findings
|-- requirements.txt                Python dependencies
|-- .gitignore                      Files excluded from Git
```

## Results summary

On the HI-Small held-out test period, the graph-enhanced XGBoost model achieved:

| Metric | Result |
|---|---:|
| PR-AUC | 0.468 |
| ROC-AUC | 0.983 |
| Precision at 1,000 alerts | 63.5% |
| Recall at 1,000 alerts | 40.7% |

The project uses a top-1,000-alert policy instead of only a probability threshold. This keeps the daily or batch review workload more stable.

## Important limitations

- The source dataset is synthetic.
- Raw account history is required to build behavior and graph features.
- Several stage scripts currently contain fixed paths and may require editing for another dataset.
- The batch feature pipeline is not a real-time API.
- At the final alert budget, many laundering transactions remain undetected.
- Model scores should be combined with case context and human investigation.

## Publish this project to GitHub

### 1. Initialize Git locally

In the project folder:

```powershell
git init
git add .
git status
git diff --cached --stat
```

Review `git status` carefully. Raw data, virtual environments, generated output directories, and Parquet/CSV outputs should appear under ignore rules and not be staged.

### 2. Make the first commit

Configure Git once if needed:

```powershell
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

Then commit:

```powershell
git branch -M main
git add .
git commit -m "Initial commit: IBM AML graph learning project"
```

### 3. Create a GitHub repository

Create an empty repository on GitHub:

1. Open https://github.com/new.
2. Enter a repository name such as `ibm-aml-project`.
3. Choose Public or Private.
4. Do not initialize it with a README, license, or `.gitignore` because this project already has these files.
5. Create the repository.

### 4. Connect the local repository and push

Copy the HTTPS URL shown by GitHub, then run:

```powershell
git remote add origin "https://github.com/YOUR_USERNAME/ibm-aml-project.git"
git push -u origin main
```

GitHub may open a browser for authentication.

For SSH instead:

```powershell
git remote add origin "git@github.com:YOUR_USERNAME/ibm-aml-project.git"
git push -u origin main
```

### 5. Update the repository later

```powershell
git status
git add .
git commit -m "Describe what changed"
git push
```

To replace a remote accidentally added with the wrong URL:

```powershell
git remote set-url origin "https://github.com/YOUR_USERNAME/ibm-aml-project.git"
```
